When doing version-control operations, use Jujutsu (`jj`) when the nearest repository checkout has `.jj` metadata, including colocated jj/Git checkouts. A nested `.git` checkout is a boundary. Do not fall back to Git if `.jj` exists but jj fails. In Git-only checkouts, use Git. Follow planner-builder's selected backend and assigned workspace/commit instructions; never manage its integration branches, edit plan state, or push unless explicitly requested.

For planner-builder workflows, use `plan_file_create` for requested planning and `plan_file_build` only when implementation is authorized. Record approved decisions, scope constraints, and exact verification criteria in the saved plan; later agents do not inherit the planner's conversation. Keep supervision off unless requested: `supervisionMode: "steer"` (`/plan-build --supervise`) allows bounded guidance, while `"advisory"` (`--advisory`) records proposals without delivery. `supervisorAgent` defaults to `"supervisor"`. Neither mode enables verifier review; use `runVerifier: true` or `--verify` only when separately requested.

Inspect the active run with `/plan-inspect` before `/plan-steer <runId> <taskId> <attemptId> <guidance>` or `/plan-cancel <runId> [taskId attemptId]`. Use current identities; accepted/queued is not delivered or completed. Steering waits for current-turn tools, not shell interruption. Closing/toggling the dashboard does not cancel a build. Respect rejected controls, finite human-question deadlines, and visible supervisor disablement; do not bypass the watchdog or integration checks.

Builder restarts are fresh conversations in the same checkout: inspect retained edits and history from the supplied base, reuse or amend only the existing task commit, and never create a second task commit or amend the base. Runner-owned plan/status/report files remain off limits. External journals/sessions are sensitive inspection records, not automatic crash recovery or reattachment; VCS recovery is authoritative. This checkout uses individual Stow links: `stow --simulate --verbose pi` is a dry-run check only. Home deployment, force/adopt/restow/prune operations, and unrelated MCP/settings cleanup are not builder tasks. See `extensions/planner-builder/README.md` for operating details.
